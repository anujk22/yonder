# Evidence that would make the entry stronger

Eligibility and winning are separate. A working Plus purchase addresses one gate. The optional person-to-person pilot is implemented in source, but a hosted two-device exchange has not been verified.

## Smallest useful user study before the deadline

Recruit three to five consenting people who recently needed to check a public place before going: a shopper, recreational player, commuter or someone planning an outing. Give each the same tasks without coaching: find a place; save it; create a collection; explain what Plus buys; explain whether Ask contacts someone today. Observe on their phone where possible. Friends or classmates can participate, but convenience sampling is not evidence that the target market is students.

Record: participant alias, date, device, task completed unaided, point of confusion, exact anonymous feedback (only with permission), fix and retest outcome. Do not invent rows. The most useful outcome is one concrete improvement you can show before/after in the film. A founder role-playing a user is an internal test.

## Minimum proof for the invited exchange

The source includes an invite-only Supabase schema, authenticated request actions, short expiry, cancellation, text answers, reports, blocks and account deletion. Before inviting testers, configure the project and prove these controls with two independent devices and identities, including blocked unauthorized reads/writes. The pilot has no media upload, evidence verification, scout payout or push notifications; local demo data does not count as a shared exchange.

The hosted project has not been deployed or tested here. Do not claim a live network until the independent-client check and answer are observed.

## Judge perspectives (role-based critique, not private knowledge of named judges)

| Lens | Hard question | Evidence to show |
| --- | --- | --- |
| Eligibility reviewer | Is it student-eligible and does the SDK actually power a purchase? | Academic email, public licensed source, native transaction + unlock, correct category |
| Engineering judge | Can I reproduce this; what is real? | Clean install instructions, exact commit, explicit demo labels, native footage |
| Product judge | Why does someone need this instead of a map or a group chat? | One specific unmet place question; honest prototype boundary; observed user behavior |
| Design judge | Is the experience useful beyond the brand? | Readable map/list flow, loading/error/empty states, accessible controls, transparent paywall |
| Business judge | Does the paid benefit have value? | Useful collections, clear price, restore/refund behavior; no manufactured revenue |
| Student judge | What did you learn and build yourselves? | Both contributors' actual roles, a real problem solved, iteration evidence and truthful tool/asset credits |

We cannot predict individual judges' private preferences or guarantee an award. The persuasive story is a coherent small product, a credible next step, and evidence of execution.
